# 03-04 — 就绪探针：数据库、迁移诊断与磁盘余量

## 目标

把 `/health/ready` 做成**能给出可行动原因**的探针，而不是一个笼统的 503。

## 必须先接受的口径（D-06 vs SC-2）

ROADMAP 的 SC-2 要求「迁移未完成 → 非 2xx」。用户在讨论阶段已决定（D-06）：`migrations` **只作诊断字段，不参与状态码**，理由是镜像内无 `prisma` CLI（`prisma` 是 devDependency，`Dockerfile:110` 明确 `--prod` 装不进来），运行时无法修复，若参与状态码会让未迁移的库陷入无限重启。

本计划按 D-06 实施。`must_haves.truths` 已把该偏差写成明文条款。`/gsd-verify-work` 与阶段 SUMMARY 必须照抄这条，**不得声称 RT-02 完整交付**。

## 边界（明确不做）

不改关闭流程（03-05）、不改启动 fail-fast 的四步顺序（03-05 负责退出码）、不改 `/health/live`（SC-1 要求它恒定轻量）。

## Tasks

### Task 1 — migrations 检查（纯逻辑 + 查询）

- **read_first**: `03-RESEARCH.md §4.5`（`_prisma_migrations` 实测结构）、`apps/api/prisma/migrations/`（目录与 `migration_lock.toml`）、`apps/api/prisma.config.ts`
- **files**: `apps/api/src/health/checks/migrations.check.ts`、`apps/api/test/migrations-check.test.ts`
- **action**:
  1. 纯函数 `compareMigrations(expectedNames: string[], appliedRows: { migration_name: string; finished_at: number | null }[])` → `{ status: 'ok' | 'pending' | 'unknown'; pending: string[]; failed: string[] }`：
     - `appliedRows` 为空且无表 → 调用方先判 `unknown`
     - 任一 `finished_at === null` → `failed` 非空 → `status: 'pending'`
     - `expectedNames` 中有未出现在 `appliedRows` 的 → `status: 'pending'`
     - 全部覆盖 → `'ok'`
  2. 读取期望迁移名的函数 `readExpectedMigrations(migrationsDir)`：用 `fs.readdirSync(dir, { withFileTypes: true })` 取子目录名（排除 `migration_lock.toml`），目录不存在时返回 `null`（表示 unknown 来源）。
  3. 查询适配 `queryAppliedMigrations(prisma)`：`prisma.$queryRaw` 读 `_prisma_migrations`；捕获「表不存在」错误并映射为 `null`，**不向上抛**。
  4. 单测覆盖四种矩阵：全 ok、缺一条、有未完成行、目录缺失/表缺失。
- **verify**:
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; node --experimental-strip-types --test "apps/api/test/migrations-check.test.ts"</automated>`
  - `<fails_when>`non-zero exit, or "# fail 0" absent, or fewer than 4 cases mapped to the ok/pending/failed/unknown matrix`</fails_when>`
- **acceptance**: 四种矩阵各有断言；`readExpectedMigrations` 对不存在目录返回 `null` 而非抛错；`queryAppliedMigrations` 对缺表返回 `null`。

### Task 2 — database 与 disk 检查

- **read_first**: `apps/api/src/prisma/prisma.service.ts`（03-01 产物）、`03-RESEARCH.md §4.6 / §8.1`
- **files**: `apps/api/src/health/checks/database.check.ts`、`apps/api/src/health/checks/disk.check.ts`、`apps/api/test/disk-check.test.ts`
- **action**:
  1. `database.check.ts`：
     - `probeWritableOnce(prisma, dir)`（**仅启动期调用**）：确认目录存在 → `fs.access(W_OK)` → 写临时文件 `.hw-write-probe` 并删除 → `prisma.$queryRaw\`select 1\``。任一步失败抛出带 `reason` 枚举的错误（`dir_missing` / `dir_readonly` / `write_failed` / `query_failed`）。
     - `checkDatabase(prisma)`（**每次 ready 调用**）：只做 `select 1`，超时 2s，返回 `{ status:'ok'|'fail', reason? }`。
  2. `disk.check.ts`：`checkDisk(dir, thresholdBytes = Number(env.DISK_MIN_FREE_BYTES ?? 10 * 1024 * 1024))` → `{ status: 'ok'|'low', freeBytes }`；用 `fs.statfsSync`，`freeBytes = bsize * bavail`；目录不存在时 `status: 'low'`、`freeBytes: 0`、`reason: 'dir_missing'`。
  3. 单测：可用字节计算（注入假 statfs）、低于阈值判 `low`、目录缺失、阈值可由 env 覆盖。
- **verify**:
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; node --experimental-strip-types --test "apps/api/test/disk-check.test.ts"</automated>`
  - `<fails_when>`non-zero exit, or "# fail 0" absent, or no case where `freeBytes < threshold` yields `low``</fails_when>`
- **acceptance**: `bsize * bavail` 计算被单测锁定；`dir_missing` 与 `low` 可区分；`DISK_MIN_FREE_BYTES` 生效。
