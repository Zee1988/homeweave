# 02-01 — workspace 骨架与最小可构建 API

<threat_model>
| ID | STRIDE | 严重度 | 威胁 | 缓解 | 验证 |
|---|---|---|---|---|---|
| T-02-01 | Tampering | medium | 为搭 workspace 一次性引入大量未钉版本依赖，任一被投毒即进入后续镜像 | 只引入最小必需集（含运行必需的 `@nestjs/platform-express`），全部进 `pnpm-lock.yaml`，CI 用 `--frozen-lockfile` | `corepack pnpm install --frozen-lockfile` exit 0 |
</threat_model>

## 目标

`apps/` 目前不存在，所以 02-03 的 Dockerfile 没有任何真实构建产物可打包。本计划建立最小但**真实可编译、可启动**的 pnpm workspace 与 NestJS 应用，并把 VER-01 要求的三条可复现命令落地。

## 边界（明确不做）

不做 `/health` 端点、不做优雅停止、不做日志脱敏、不做数据库（02-02 负责）、不做 Docker。Nest 启动后只监听端口并打印默认启动日志。

## Tasks

### Task 1 — 建立 pnpm workspace

- **read_first**: `package.json`、`.gitignore`、`docs/03_TECH_STACK_AND_REPO.md`
- **files**: `pnpm-workspace.yaml`（新建）、`.gitignore`（补条目）、`package.json`（改 scripts）
- **action**:
  1. 新建 `pnpm-workspace.yaml`，内容仅 `packages:` 下两行 `- "apps/*"` 与 `- "packages/*"`（`packages/` 目录暂不存在也合法，为后续共享包预留）。
  2. `package.json` 的 `scripts` 增加三条（**不得删除**现有 `generate:app`/`validate:app`/`check:app`/`test:app`）：
     - `"lint": "node scripts/lint-workspace.mjs"`
     - `"typecheck": "node scripts/typecheck-workspace.mjs"`
     - `"test": "corepack pnpm@9.15.4 run test:app && corepack pnpm@9.15.4 -r --if-present test"`
       - **为什么不用裸 `pnpm`**：未执行 `corepack enable` 的机器上没有 `pnpm` shim，pnpm 执行 script 时用 `cmd.exe` 解析，会报 `'pnpm' is not recognized` → `pnpm test` 必红。用 `corepack`（Node 22 自带）+ 固定 `@9.15.4` 与 CI 的 `pnpm/action-setup` 版本对齐，且不违反「根 package.json 不得加 `packageManager`」的禁令。
  3. `.gitignore` 增加 `apps/*/dist/`、`node_modules/`、`*.tsbuildinfo`、`.env`、`.env.local`（若已存在同名条目则跳过，**不要重复**）。
- **verify**:
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; node -e "const y=require('js-yaml');const d=y.load(require('fs').readFileSync('pnpm-workspace.yaml','utf8'));if(!Array.isArray(d.packages)||!d.packages.includes('apps/*')){console.error('workspace missing apps/*');process.exit(1)};const s=Object.keys(require('./package.json').scripts);const need=['generate:app','validate:app','check:app','test:app','lint','typecheck','test'];const miss=need.filter(k=>!s.includes(k));if(miss.length){console.error('missing scripts',miss.join(','));process.exit(1)};console.log('ok')"</automated>`
- **acceptance**: workspace 文件可被 js-yaml 解析且含 `apps/*`；根 scripts 同时存在新增三条与原有四条。

### Task 2 — 建立 apps/api 最小 NestJS 应用

- **read_first**: `package.json`（engines.node >= 22）、`docs/21_HOME_ASSISTANT_APP_DEPLOYMENT.md`（ingress_port 8099）
- **files**: `apps/api/package.json`、`apps/api/tsconfig.json`、`apps/api/src/main.ts`、`apps/api/src/app.module.ts`
- **action**:
  1. `apps/api/package.json`：`name: "@homeweave/api"`、`private: true`、`version: "0.0.0"`（**与 HA App 的 0.1.0 无关，注释写明**）、`main: "dist/main.js"`、scripts：
     - `"build": "tsc -p tsconfig.json"`
     - `"typecheck": "tsc -p tsconfig.json --noEmit"`
     - `"start": "node dist/main.js"`
  2. 依赖：`@nestjs/core`、`@nestjs/common`、**`@nestjs/platform-express`**、`reflect-metadata`、`rxjs`；devDependencies：`typescript`、`@types/node`。**不引入 `@nestjs/cli`**（构建只用 tsc，减少攻击面与体积）。
     - `@nestjs/platform-express` 虽在 `@nestjs/core` 里是 **optional peer**（不装不会报 peer 警告），但 `NestFactory.create()` 没有它会在运行期抛错，Task 5 的启动冒烟必然失败 —— 它是运行必需的，不属于「可省的最小集之外」。
  3. `tsconfig.json`：`target: "ES2022"`、`module: "commonjs"`、`outDir: "dist"`、`rootDir: "src"`、`strict: true`、`experimentalDecorators: true`、`emitDecoratorMetadata: true`、`declaration: false`、**`sourceMap: false`**（IMG-02 要求镜像内无 `.map`，从源头断掉）、`skipLibCheck: true`。
  4. `app.module.ts`：`@Module({})` 空模块 + 一行注释说明控制器由后续阶段加入。
  5. `main.ts`：`NestFactory.create(AppModule)`，`const port = Number(process.env.PORT ?? 8099)`（对齐 docs/21 的 `ingress_port: 8099`），`await app.listen(port, '0.0.0.0')`。
- **verify**:
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; corepack pnpm install --lockfile-only; corepack pnpm install; corepack pnpm --filter @homeweave/api build; if (-not (Test-Path apps/api/dist/main.js)) { exit 1 }; node -e "const fs=require('fs');const s=fs.readFileSync('apps/api/dist/main.js','utf8');if(s.includes('sourceMappingURL'))process.exit(1);console.log('ok')"</automated>`
- **acceptance**: `apps/api/dist/main.js` 存在且不含 `sourceMappingURL`；`pnpm-lock.yaml` 已生成且其 `importers` 含 `.` 与 `apps/api` 两项；`apps/api/dist` 被 `.gitignore` 的 `dist/` 规则忽略（`git check-ignore -v` 可证）。

### Task 3 — lint 入口（零依赖）

- **read_first**: `scripts/validate-app-metadata.mjs`（现有脚本的代码风格与错误输出格式）
- **files**: `scripts/lint-workspace.mjs`、`scripts/lint-workspace.test.mjs`
- **action**: 实现一个零依赖（仅允许 `node:` 内置 + 已存在的 `js-yaml`）的 lint 脚本，对下列内容逐项检查，任一失败即 `process.exitCode = 1` 并打印 `✗ <file>: <reason>`：
  1. 仓库内所有 `*.mjs` 通过 `node --check`（用 `child_process.execFileSync` 调 `process.execPath`，不引入解析库）。
  2. 所有 `*.yaml`/`*.yml`（含 `.github/workflows/*.yml`，若已存在）可被 `js-yaml` 解析；解析失败报文件名与行号。
  3. 所有 `*.json`（`package.json`、`apps/api/package.json`、`homeweave_app/app-metadata.json`）可 `JSON.parse`。
  4. 显式排除 `node_modules/`、`dist/`、`.git/`、`.planning/`。
  5. 成功时打印 `✓ lint passed (<n> files)`，与 Phase 01 的 `✓ 87 checks passed` 风格一致。
- **verify**:
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; corepack pnpm lint; if ($LASTEXITCODE -ne 0) { exit 1 }; 'ok'</automated>`
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; node --test scripts/lint-workspace.test.mjs; if ($LASTEXITCODE -ne 0) { exit 1 }; 'ok'</automated>`
- **acceptance**: `pnpm lint` exit 0 且输出计数；测试文件至少覆盖「坏 JSON → exit 1」「坏 YAML → exit 1」「合法输入 → exit 0」三例。

### Task 4 — typecheck 入口

- **read_first**: `apps/api/tsconfig.json`（Task 2 产物）
- **files**: `scripts/typecheck-workspace.mjs`、`scripts/typecheck-workspace.test.mjs`
- **action**: 脚本执行 `pnpm -r --if-present typecheck`（子进程转发，保持退出码透传）。若递归结果中**没有任何包声明 typecheck**，必须打印 `✗ no workspace package declares typecheck` 并 exit 1 —— 不允许"没东西可查就成功"，那正是 VER-01 想禁止的假绿。
  - **子进程怎么调 pnpm**（与 Task 1 同一个坑）：裸 `pnpm` 在未 `corepack enable` 的机器上不可解析。因此：通过 `pnpm run typecheck` 调用时用 `npm_execpath` 指向的 pnpm JS 入口（`node <execpath> -r ...`，跨平台且不依赖 shim）；直接 `node scripts/typecheck-workspace.mjs` 时回退 `corepack pnpm@9.15.4 -r ...`（经 shell 解析 `.cmd`）。两条路径都已实测 exit 0。
  - 「是否声明 typecheck」用 `pnpm-workspace.yaml` 的 `packages:` 模式枚举目录后读各包 `package.json` 判定，只支持 `prefix/*` 形式（本仓库仅此一种，避免为零依赖引入 glob 实现）。
- **verify**:
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; corepack pnpm typecheck; if ($LASTEXITCODE -ne 0) { exit 1 }; node --test scripts/typecheck-workspace.test.mjs; if ($LASTEXITCODE -ne 0) { exit 1 }; 'ok'</automated>`
- **acceptance**: 存在 `apps/api` 的 typecheck 时真实执行 `tsc --noEmit`；人为把 `main.ts` 改成语法/类型错误时该命令 exit 1（用一次临时改动+还原验证，**不要把错误留在工作树**）。
