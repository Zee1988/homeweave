# 03-02 — 探针语义收窄与 watchdog 生成链

## 目标

两件与运行时进程无关、但与「这个镜像到底能不能信」直接相关的事：

1. **把 `RUST_FREE` 从一句会被误读的结论，拆成两个可核对的结论**（D-05a）。引入 `better-sqlite3` 后，探针如果只说 `RUST_FREE`，等于宣称「没有原生代码」，而事实相反。
2. **让 HA 真正能重启挂死的 app**（D-13）。`watchdog` 必须走生成器，因为手改 YAML 会被 `--check` 判红，且 `assertConsumedKeys` 会静默丢弃未消费的键。

## 边界（明确不做）

不改 `apps/api/src`（03-01 负责）、不改 `assert-image.sh` 的检查项数量（03-05 负责，因为它依赖 `/health/live` 真的存在）。

## Tasks

### Task 1 — 探针扩展到全量原生模块

- **read_first**: `scripts/probe-prisma-engine.mjs`、`scripts/probe-prisma-engine.test.mjs`、`03-RESEARCH.md §4.4`、`apps/api/prisma/ENGINE_DECISION`
- **files**: `scripts/probe-prisma-engine.mjs`、`scripts/probe-prisma-engine.test.mjs`
- **action**:
  1. 保留现有的 Prisma client 输出目录扫描与 `ENGINE_DECISION=RUST_FREE` 输出（**字面量不能变**，02 阶段的断言与文档依赖它）。
  2. 新增第二个扫描面：`node_modules/**/*.node`（跟随 pnpm 的 symlink，用 `fs.realpath` 去重，避免同一二进制被计多次）。输出一行：
     ```
     NATIVE_MODULES=<空> | comma-separated package names
     ```
     例如 `NATIVE_MODULES=better-sqlite3`。
  3. 新增一行解释性输出（供人读，机器断言不依赖）：
     ```
     RUST_FREE_SCOPE=prisma-engine-only   # native modules may still exist; see NATIVE_MODULES
     ```
  4. 扫描必须容忍三种环境：无 `node_modules`（纯仓库）、pnpm 符号链接布局、Windows 路径分隔符。
  5. 测试新增用例（不改旧用例的目录布局假设）：
     - `node_modules/better-sqlite3/prebuilds/linux-x64.node` 存在 → `NATIVE_MODULES` 含 `better-sqlite3`，且 `ENGINE_DECISION` 仍是 `RUST_FREE`
     - 仅有 client 目录下的 `.node` → `ENGINE_DECISION` 不再是 `RUST_FREE`（旧行为保留）
     - 无 `node_modules` → `NATIVE_MODULES=` 为空、不崩溃
- **verify**:
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; node --test "scripts/probe-prisma-engine.test.mjs"</automated>`
  - `<fails_when>`non-zero exit, or "# fail 0" absent, or "NATIVE_MODULES" not asserted in any test name`</fails_when>`
- **acceptance**: 三个新用例存在且通过；`ENGINE_DECISION` 字面量未改；`RUST_FREE_SCOPE` 行出现在输出里。

### Task 2 — 生成器支持 `watchdog`

- **read_first**: `scripts/generate-app-metadata.mjs`（`APP_SOURCE_KEYS`、`buildConfigYaml()`、`assertConsumedKeys()` 及其注释里的 `app.watchdog = true` 反例）、`homeweave_app/app-metadata.json`、`03-RESEARCH.md §9.1/§9.2`
- **files**: `scripts/generate-app-metadata.mjs`、`homeweave_app/app-metadata.json`、`homeweave_app/config.yaml`
- **action**:
  1. `app-metadata.json` 的 `app` 段新增 `watchdog: "http://[HOST]:[PORT:8099]/health/live"`（字符串 URL，与 `ingress_port: 8099` 一致）。
  2. `generate-app-metadata.mjs`：把 `watchdog` 加入 `APP_SOURCE_KEYS`，并在 `buildConfigYaml()` 中按契约位置输出 `watchdog: "<url>"`。位置紧随 `ingress_port`（语义相邻），且**必须在 `01-PATTERNS.md` 记录的顺序契约内确定**；一旦确定，测试用固定字符串整体比对，不要写成「包含该行」。
  3. `validate-app-metadata.mjs`：若它维护独立的键白名单或类型校验，同步允许 `watchdog` 且断言其为以 `http://` 或 `https://` 开头的字符串（**不接受 `true`**）。
  4. 跑 `corepack pnpm generate:app` 重新生成 `config.yaml`（与 `repository.yaml` 若受影响）。
