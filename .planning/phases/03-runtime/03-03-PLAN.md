# 03-03 — 结构化日志：递归脱敏与 requestId 串联

## 目标

满足 RT-04 的两半：**结构化**（机器可解析）与**脱敏**（凭证不落盘），并给每条日志一个能串联同一请求的 `requestId`。

## 边界（明确不做）

不改健康检查（03-04）、不改关闭流程（03-05）、不引入 `pino-http`。

## 为什么不引入 `pino-http`

`pino-http` 的价值是自动 `req`/`res` 序列化与自动 requestId，代价是它把 `req` 整体交给序列化器 —— 而本次泄露风险的高发点是 `err.config.headers` 这类**非 `req` 结构**，`pino-http` 覆盖不到。自写中间件 + `sanitize()` 覆盖更完整，且少一个与 pino 10 的版本耦合点。后续若需要访问日志的状态码/耗时，从 `res.on('finish')` 补即可，不必换库。

## Tasks

### Task 1 — `sanitize()` 递归脱敏

- **read_first**: `03-RESEARCH.md §5.2`（pino `redact` 的三处能力边界）、`AGENTS.md`（secrets 不得进日志）
- **files**: `apps/api/src/logging/sanitize.ts`、`apps/api/test/sanitize.test.ts`
- **action**:
  1. 导出 `REDACTED = '[REDACTED]'`、`MAX_DEPTH = 6`。
  2. 键名黑名单（小写比对，命中即整值替换）：`authorization`、`cookie`、`set-cookie`、`x-api-key`、`x-auth-token`、`token`、`access_token`、`refresh_token`、`id_token`、`apikey`、`api_key`、`password`、`passwd`、`secret`、`client_secret`、`ha_token`、`supervisor_token`。
  3. 值模式（仅字符串值，命中片段替换为 `***REDACTED***`）：`/\bBearer\s+[A-Za-z0-9._~+/=-]{8,}/i`、`/\bToken\s+[A-Za-z0-9._~+/=-]{8,}/i`、`/\bBasic\s+[A-Za-z0-9+/=]{8,}/i`、`/\bsk-[A-Za-z0-9]{16,}/`、`/\bghp_[A-Za-z0-9]{20,}/`、`/\beyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\./`。
  4. 递归规则：`Date`/`RegExp` 原样；`Buffer` → `'<Buffer n bytes>'`；`Error` → `{ name, message, stack, cause }`（`cause` 递归）；数组保序；`Map`/`Set` 转数组；`WeakSet` 记已访问 → `'[Circular]'`；`depth > MAX_DEPTH` → `'[MaxDepth]'`；**始终返回新对象**。
  5. 单测：11 个键名逐个命中；6 种值模式；`a.self = a`；7 层嵌套；同对象内 `headers.accept` 保留而 `headers.authorization` 被掩码；不修改入参。
- **verify**:
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; node --experimental-strip-types --test "apps/api/test/sanitize.test.ts"</automated>`
  - `<fails_when>`non-zero exit, or "# fail 0" absent, or no test covers circular / maxdepth / input-not-mutated`</fails_when>`
- **acceptance**: 全部用例通过；`sanitize(obj) !== obj` 且 `JSON.stringify(obj)` 未被改变；自引用不抛异常。
