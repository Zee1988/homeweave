# 03-01 — tracer 切片：依赖、配置解析、Prisma adapter 与 `/health/live`

## 目标

建立一条**端到端最薄的可运行链路**：进程能起、能解析三条配置、能通过 driver adapter 打开 SQLite、能对外回答 `/health/live`。这条链路跑通后，03-03/03-04/03-05 才有东西可挂。

## 边界（明确不做）

不做脱敏（03-03）、不做 `/health/ready`（03-04）、不做 fail-fast 与优雅关闭（03-05）、不碰生成器与探针（03-02）。本计划的 logger 只做「结构化 + 级别」，`sanitize()` 在 03-03 接入。

## Tasks

### Task 2 — 配置解析（三条，纯函数）

- **read_first**: `apps/api/prisma.config.ts`（现有 CLI 侧解析）、`.env.example`、`homeweave_app/config.yaml`（`ingress_port: 8099`、`options.logLevel` 默认值）
- **files**: `apps/api/src/config/app-config.ts`、`apps/api/src/config/database-url.ts`、`apps/api/src/config/log-level.ts`、`apps/api/test/database-url.test.ts`、`apps/api/test/log-level.test.ts`
- **action**:
  1. `database-url.ts` 导出 `resolveDatabaseUrl(env: NodeJS.ProcessEnv): string`：返回 `env.DATABASE_URL ?? 'file:/data/homeweave.db'`；再导出 `databasePathFromUrl(url: string): string`，用**与适配器相同**的规则 `url.replace(/^file:/, '')` 得到文件路径，供 03-04 的 disk 检查使用。
     - 注释必须写明：「此处不重复实现协议剥离，仅为让 disk 检查与适配器看到同一路径；规则以 `dist/index.js` 的 `url.replace(/^file:/,'')` 为准」。
  2. `log-level.ts` 导出 `resolveLogLevel(env, optionsFileReader): { level, source }`：优先级 `LOG_LEVEL` → `/data/options.json` 的 `logLevel` → `info`。读文件失败/JSON 损坏一律回落 `info` 且 `source: 'fallback'`，**不抛出**。
     - 合法级别集合以 `homeweave_app/app-metadata.json` 的 `optionDefs.logLevel.values` 为准（当前 `info|debug|warn`）；超出集合的值降级为 `info` 并在返回值里标记 `source: 'invalid'`。
  3. `app-config.ts` 导出 `loadAppConfig()`，聚合 `port`（`Number(env.PORT ?? 8099)`，非有限数或越界 [1,65535] 时抛 `ConfigError`）、`databaseUrl`、`databasePath`、`logLevel`。
  4. 两个单测覆盖：`DATABASE_URL` 缺省/绝对/相对/`file:` 前缀；级别优先级与非法值回落。
- **verify**:
  - `<automated>cd d:/workSpace/HomeWeave/homeweave; node --experimental-strip-types --test "apps/api/test/database-url.test.ts" "apps/api/test/log-level.test.ts"</automated>`

- **acceptance**: 四个 URL 变体都返回预期路径；`LOG_LEVEL=garbage` 返回 `{ level: 'info', source: 'invalid' }`；`options.json` 不可读时不抛异常。
